`.emit(...)` on a field declared as `EventEmitter2` is now classified as `event.publish`, whatever the field is called. Only the receiver names `eventBus` and `EventEmitter2` were recognised, so the injection NestJS documents, `constructor(private readonly eventEmitter: EventEmitter2)` with `this.eventEmitter.emit("order.created", …)`, stayed a plain call and `aburi diff` reported adding one as a syntax-only change. The type must be the `EventEmitter2` the file imports from `@nestjs/event-emitter` or `eventemitter2`, under its own name, an alias, a namespace or `eventemitter2`'s default import; the effect is `high` confidence and tagged `effects-plugin:nest:EventEmitter2.emit`. A field declared with another type, such as a socket.io `Server`, stays a call, and a receiver named `eventBus` is still recognised by its name whatever its type. An IR scanned before this release reports such a method, and every caller its effect propagates to, as a logic change once, which trips `--fail-on logic-changed` or `changed`. Rescan the base rather than comparing against a stored IR. This needs `@aburi/lang-typescript` from the same release, which reads the declared type.
