A union or intersection type broken over lines with a leading operator is now recorded without that operator. A formatter writes `provider:\n  | ClassProvider\n  | FactoryProvider` when it breaks the type and `provider: ClassProvider | FactoryProvider` when it joins it, and the plugin kept the leading `|` in `signature.inputs[].type`, so joining the type moved the `api` fingerprint and put the Symbol in ⚠ API changes with a row that differed only by that `|`. The operator is read off the syntax tree, so it goes wherever the type is written — a parameter, a return type, a type predicate (`x is | A | B`), a function type's return, a generic argument (`Map<string, | A | B>`), a type parameter's constraint — and a `|` or `&` inside a string literal type stays. The rest of the text is kept as written.

This moves the `api` fingerprint of every Symbol whose signature carries such a type, once, so an IR scanned before this release, compared with one scanned after, reports those Symbols as API changes and trips `--fail-on api-changed` or `changed`. In the public-repository benchmark's `nest` diff, ⚠ API changes drop from 7 Symbols to 3: `Module.addCustomProvider` and `Module.addCustomExportedProvider` become unchanged, and `LazyModuleLoader.load` and `Module.isCustomProvider` keep only their logic change. On this repository, scanning one tree with both versions gives a byte-identical set of Symbols and fingerprints. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
