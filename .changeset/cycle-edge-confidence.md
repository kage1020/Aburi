Effect propagation now weighs the confidence of the calls inside a call cycle. A propagated effect carries the confidence of the weakest link on its strongest path, a call or the effect's own classification, but the members of a cycle all took one value for the whole cycle, the strongest any of them reached, so a call back into a caller raised the caller's confidence in an effect although the call opened the caller no better path to it. With `Service.run` calling `Store.save` across a namespace call resolved at component scope (`medium`), and `Store.save` writing through `prisma.invoice.create`, adding `if (n > 0) Service.run(n - 1)` to `Store.save` turned `Service.run`'s propagated `db.write` from `medium` to `high`, the Markdown projection dropped its `⚠ medium` badge, and every caller outside the cycle read the raised value too. Each member of a cycle now holds its own confidence in each effect, combined across the calls inside the cycle the way it is along any other path, and a caller outside the cycle reads the confidence of the member it calls: `Service.run` stays at `medium` with or without the call back. Which effects each Symbol carries, and their `plugin`, `derivedBy` and `derivedFrom`, are unchanged; only `confidence` moves.

No fingerprint reads an effect's confidence, so no `api`, `logic` or `syntax` value moves and a diff across the upgrade reports no Symbol as changed for this. A Symbol in or above a cycle whose propagated effect was raised this way carries the lower `confidence` in an IR scanned after this release. Where such a Symbol is changed for another reason, a diff whose base IR was scanned before this release lists that effect under `effects modified`. The Markdown report does not print a propagated effect's `confidence`, so that row reads exactly as it would for the base's entry: it is the confidence that moved, as the Symbol's `before` and `after` in `diff.json` show, not a spurious entry. The row appears in every such comparison for as long as the base IR is one scanned before this release: rescan the base to keep it out of the report. `aburi diff <base>..<head>` scans both sides and is unaffected.
