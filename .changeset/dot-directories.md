Files in a directory whose name starts with a dot, and dot files, are now scanned. Discovery kept every path with a dot-prefixed segment out, as a side effect of keeping `.git` out, so a GitHub Action written in TypeScript under `.github/actions/<name>/src`, Storybook's configuration in `.storybook` or a VitePress theme in `docs/.vitepress` got no Symbols, no place in `stats.totalFiles` and no `stats.skippedFiles` entry, and `ignore` could not bring them back. With `src/a.ts`, `.github/actions/deploy/src/main.ts` and `.storybook/main.ts` tracked, `aburi scan` printed `1 kept · 0 dropped · 1 files`; it now prints `3 kept · 0 dropped · 3 files`, with `ts:.github/actions/deploy/src/main.ts#run` and `ts:.storybook/main.ts#config` beside `ts:src/a.ts#a`. No walk lists a `.git`, whatever its patterns spell, and a directory below the workspace root that holds one, a `.git` directory or the `gitdir:` file a linked worktree or a submodule keeps, is another checkout whose files are not scanned. That covers a worktree at `.worktrees/feat` or `.claude/worktrees/feat`, a nested repository, a populated submodule, and the base worktree `aburi diff` creates under an in-repository `TMPDIR`; a `.git` file that is not a `gitdir:` pointer marks nothing. Yarn's `.yarn/`, `.pnp.cjs` and `.pnp.loader.mjs` are core patterns: Yarn's own setup commits its release, plugins and editor SDKs, and under zero-installs its Plug'n'Play loader. So is VitePress's `.vitepress/cache/`, which `vitepress init` leaves out of `.gitignore`. In `ignore`, in the core patterns and in a language plugin's drop patterns, `*` and `**` now match a name that starts with a dot, so `"ignore": ["docs/**"]` leaves out `docs/.vitepress/` as well.

Component detection follows: the language census counts files in dot directories, and the nx detector finds a `project.json` in one, as nx itself does. Neither reads another checkout, and the nx search passes over `.nx/cache`, `.nx/workspace-data` and `.yarn/cache`, as nx's own walk does, whatever `.gitignore` says. The resolution of `pnpm-workspace.yaml` and `workspaces` patterns still reads them as pnpm and npm do: `packages/*` does not match `packages/.template`, `.github/actions/*` matches `.github/actions/deploy`, and a package in a nested checkout is still found.

What an IR scanned before this release, compared with one scanned after, shows:

- Files of a claimed extension under a dot directory, and dot files such as `.eslintrc.js`, are scanned, so their Symbols are reported as added, once, and a gate on `added` trips. A file among them over `maxFileSizeBytes` now appears in `stats.skippedFiles`. Calls into them now resolve, so their callers gain `dependencies[]` edges and, with an effect plugin loaded, the effects that propagate along them, which moves those callers' `logic` fingerprints.
- The language census counts every extension it knows, whether a plugin claims it or not, so ten or more `.github/scripts/*.py` files that are at least 5% of a component's files add `py` to its `languages`, and `aburi init` writes that into `aburi.json`. An nx project kept in a dot directory becomes a Component of its own, taking its files' Symbols from the Component that held them.
- A checkout nested in the workspace is no longer scanned, wherever it sits. One in a directory without a leading dot (`worktrees/feat`, a nested repository, a populated submodule) was scanned as part of the workspace around it: its Symbols leave the Document, and an nx project in it is no longer a Component. `aburi diff` already left submodules out of both file scans.
- A dot directory that cannot be listed and that `.gitignore` does not exclude, such as a container's `.pgdata/` owned by another user, now ends the run at exit 1, as any directory that cannot be listed does. No walk entered one before.

On this repository, scanning one tree with both versions counts four more files under `docs/.vitepress/` and `.claude/`, adds 18 Symbols from two of them, one of those dropped, and one dependency edge between them, and moves no fingerprint.

Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with this release, so each of these changes shows on both sides or on neither.
