LSP enrichment no longer guesses which class a hover means when two files declare a class of that name. A hover gives the owner class by name only (`(method) Repository.save()`), and when the caller's file declared nothing of that name the pass took the first one by Symbol id, so `this.save()` in a class extending `models/repository.ts`'s `Repository` could get a `high` edge into `lib/repository.ts`, a file the caller never imports. It now takes a class of that name in the caller's file, and otherwise the one class of that name elsewhere; when there are several, it writes no hint and counts the hover under `hintsRejected.ownerClassNotFound`. Among several, a dropped class that lacks the member is set aside, while a dropped class that has it still counts. Something of that name in the caller's file that is not a class, such as an interface or a `const` holding an object literal, is passed over; a `const` there used to give the call a `high` edge into the object's member. `@aburi/types` carries the reworded description of that bucket.

The member is now looked up only in the file that declares the owner class, under that class's id with the member's name appended. The pass used to try the caller's file and then take any Symbol in the language named `Repository.save`, wherever it was, and that search by name is gone. A member that is not where the owner class's id says, or a class in the caller's file that lacks the member while another file's class has it, now leaves the call without a hint and is counted under `hintsRejected.memberNotFound`.

A call these rules now decline could be resolved before, to a class or member the name alone could not single out, whether or not it was the one meant; and a call that went into a `const`'s member now goes to the class. With an effect plugin loaded, the caller loses that callee's effects or takes another's, and so does every Symbol in its transitive callers' closure, so each one's `logic` fingerprint moves unless it already carries an effect on that target. An IR scanned before this release, compared with one scanned after, can therefore report any of them as changed. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed version and is unaffected.
