A qualified call whose head the caller's file binds to a declaration now stops at that declaration when it lacks the member. `Logger.log()` in a file that declares `class Logger extends Object {}`, or that imports `Logger` from a relative module declaring it, used to go on to component and workspace scope, which compare the whole target with `Symbol.name` and ignore bindings, so it linked to another file's instance method `Logger.log`, gained a `via: "call"` dependency on it and inherited its effects: a `db.write` from a file the caller cannot reach. It is now unresolved, bucketed `no-match`, as a missing member already was when nothing else in the workspace shared its name. The same holds for an aliased import (`import { Logger as B }`, `B.log()`), a default import of a module whose default export is the class, and a namespace import of a module that declares the next segment (`ns.Logger.log()`). A head bound by nothing, by a bare specifier (how a call into a workspace package reaches its Symbol today), by a relative import of a module the scan has no Symbol in, or by one that does not itself declare the name, such as a barrel re-exporting it, still reaches component and workspace scope.

A call that no longer resolves leaves `calls[].resolved` and `dependencies[]` and takes the effects it carried with it, and `stats.callResolution` counts it under `noMatch` instead of `resolvedCalls`. Because `logic` is computed after effect propagation, the caller and every caller that inherited those effects move `logic` although nobody edited them. An IR scanned before this release, compared with one scanned after, reports them as logic changes and trips `--fail-on logic-changed` or `changed`. No `api` or `syntax` fingerprint moves. On this repository, which loads no effect plugin, scanning one tree with both versions gives a byte-identical IR. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
