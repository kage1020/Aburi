A qualified call whose head is bound to a declaration that lacks the member now stops there, instead of linking to a same-named member of another file. Two cases used to go on to component and workspace scope, which compare the whole target with `Symbol.name` and ignore bindings.

- **The head is bound to a declaration whose members are Symbols:** a class, enum or namespace, or a `const` holding an object literal, whether the caller's file declares it or a named import of a module declaring it binds it. Before, `Logger.log()` beside `class Logger {}` or through `import { Logger } from "./base-logger"` linked to another file's instance method `Logger.log`. It gained a `via: "call"` dependency on that method and inherited its effects: a `db.write` from a file the caller cannot reach. A dropped declaration binds as well, so `class Logger { level = 1 }`, dropped as a pure DTO, stops the search too. In the caller's own file, a kept member of such a dropped declaration is now reached, as an import of it already was. So `Config.load()` beside `class Config { static readonly A = 1 }` and `namespace Config { export function load() {} }` now resolves to `Config::load`.
- **An alias, a default import or a namespace import binds the head.** Component and workspace scope could only match such a target to a namesake, so `B.log()` through `import { Logger as B } from "./barrel"`, `L.log()` through a default import of a module with no default export or of an anonymous `export default class`, and `ns.Logger.log()` all stop. This holds for a bare specifier too: `path.join()` through `import * as path from "node:path"` stays bucketed `external`, and no longer links to a workspace Symbol named `path.join`.

Both cases are now unresolved, bucketed `no-match` (`external` for a bare specifier), as a missing member already was when nothing else in the workspace shared its name. Other heads still reach component and workspace scope: a head bound by nothing; a `const` from `require(...)`, from a destructuring or from any value the resolver cannot see; a `declare`d one; a function. So does a named import that keeps the exported name of a bare specifier, of a module with no Symbol, or of a module that does not declare the name, such as a barrel re-exporting it. That is how such a call reaches the declaration it names.

A call that no longer resolves leaves `calls[].resolved` and `dependencies[]`, with or without an effect plugin, and takes any effects it carried with it. `stats.callResolution` counts it under `noMatch` (or `external`) instead of `resolvedCalls` or `ambiguous`. A call that now resolves moves the other way. Where an effect plugin classified the callee's calls, the caller and every caller that inherited those effects move `logic` although nobody edited them. An IR scanned before this release, compared with one scanned after, then reports them as logic changes and trips `--fail-on logic-changed` or `changed`. No `api` or `syntax` fingerprint moves. On this repository, scanning one tree with both versions gives a byte-identical IR: none of its 8,630 calls is resolved differently. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
