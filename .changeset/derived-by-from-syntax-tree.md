---
"@aburi/framework-express": minor
"@aburi/framework-react": minor
---

The Express and React plugins now name a call in `derivedBy` from the syntax tree instead of copying the callee's source text. A chain a formatter wrapped over several lines put its line breaks and indentation into the entry (`framework:express:route:router\n  .delete`), a comment inside the chain was copied in, and a `;` in that comment split the entry in two, because the pipeline splits a classification's `derivedBy` on `;` (`router // admin; see the runbook\n  .use(…)` gave `framework:express:error-middleware:router // admin` and ` see the runbook\n  .use`). A receiver written `(app as Express)` left an empty name, `framework:express:route:.get`, `app!.get(…)` gave `app!.get`, `app?.get(…)` gave `app?.get`, and `require('express').Router()` and `require("express").Router()` gave different entries for the same call. The route, middleware, error-middleware and mount entries are now `<receiver>.<method>`: the method called and the name the receiver chain starts from, read through parentheses, `as`, `satisfies` and `!` and through every call on the way, which is the value `@aburi/lang-typescript`'s `call-statement:` entry on the same Symbol carries. Those calls are now `router.delete`, `router.use`, `app.get` and `require.Router`. The error-middleware and mount entries of a chained `.use(…)` follow that reading as the route and middleware entries already did, so `app.use(cors()).use("/api", apiRouter)` is `framework:express:mount:app.use` rather than `framework:express:mount:app.use(cors()).use`, and a Router is named by its factory the same way (`express.Router`, `Router`). The React plugin names a `createContext`, `forwardRef` or `memo` call the same way: `React\n  .memo(Inner)`, `(React as any).memo(Inner)` and `React?.memo(Inner)` are `framework:react:memo:React.memo`, `loadReact().memo(Inner)` is `framework:react:memo:loadReact.memo`, and a receiver that is not a name is `<computed>`: `new Registry().memo(Inner)` gives `framework:react:memo:<computed>.memo`, and so does `(<any>React).memo(Inner)`, because a `<T>x` assertion is not read through.

The method is now the callee's property rather than whatever followed the last `.` in its text, so a call whose `.` ends a line (`app.\n  get("/users", listUsers)`, `React.\n  memo(Inner)`) or is followed by a comment holding a `.` is classified as its one-line spelling is, where it was left unclassified. The React plugin's hook detection reads a call the same way, so `React.\n  useState(0)` in a `use*` function now gives `framework:react:hook:hook-call` as `React.useState(0)` does. Both plugins read a callee through `@aburi/core`'s `calleeName`; a const's call is still the one `declaratorValue` reads from its own declarator.

Both plugins stop re-exporting `calleeText` and `calleeLeaf` from `@aburi/core`, which read a callee's text; import them from `@aburi/core` if you still need them. `@aburi/framework-express` no longer exports `calleeRoot`, which read a receiver out of the callee's text; `calleeName(call).name` gives the receiver and method. `RouterCall` and the React plugin's `WrapperCall` are now `@aburi/core`'s `CalleeName`, `{ name, leaf }`: the field that held the callee's text, `callee`, is `name`, which holds `<receiver>.<method>`.

No fingerprint reads `derivedBy` and `aburi diff` does not compare it, so an IR scanned before this release, compared with one scanned after, differs in those entries only inside the IR and in `aburi explain`. A call that is now classified gains its `extKind`, which the `api` fingerprint reads: it is reported as an api change, and the Markdown projection's Boundary effect surface, which lists Symbols by a `framework:` extKind, gains it if it has effects. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
