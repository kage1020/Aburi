A call whose receiver is written behind `as`, `satisfies` or an old-style `<T>x` assertion now has the target of the receiver it asserts about. The assertion answered with its whole text, type included, so `(emitter as Foo.Bar).update(x)` was `emitter as Foo.Bar.update`, a dynamic call of four segments. In a file importing `@prisma/client`, `effects-prisma` classified it as a medium `db.write`, because it has the three segments a delegate call has, while `emitter.update(x)` written plainly is no effect. `(db as Drizzle.DB).insert(r)` was likewise `db as Drizzle.DB.insert`. A type that spelled a spread or spanned lines (`(x as [...T]).map(g)`) collapsed the receiver to `<computed>`. Each now reads as the receiver without its type, `emitter.update`, `db.insert`, `x.map`, `this.repo.save` for `(this.repo as Repo).save()`, with no `dynamicReceiver`, so it can resolve and classify as the plain spelling does. A receiver that is not a name stays dynamic (`([...a] as T).m()` is `<computed>.m`). A non-null assertion keeps its text around a name (`svc!.save`).

`calls[].target` changes for every such call, and such a call leaves `stats.callResolution`'s `dynamic` bucket; some start resolving. Where an effect plugin classifies one, `effects[].target` changes too, and it is a `logic` input, so an IR scanned before this release, compared with one scanned after, reports those Symbols as logic changes, and the asserted-receiver calls `effects-prisma` classified by their segment count stop being effects. On this repository, scanning one tree with both versions changes the target of 21 calls (`(input as LocationLink[]).map` is now `input.map`), moves 20 of them from `dynamic` to `no-match` and one to `local-scope`, and moves no fingerprint. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
