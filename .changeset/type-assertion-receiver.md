A call whose receiver is written behind `as`, `satisfies` or an old-style `<T>x` assertion now has the target of the receiver it asserts about. The assertion answered with its whole text, type included, so `(emitter as Foo.Bar).update(x)` was `emitter as Foo.Bar.update`, a dynamic call of three segments. In a file importing `@prisma/client`, `effects-prisma` classified it as a medium `db.write`, because three is the count a delegate call has, while `emitter.update(x)` written plainly is no effect. In a file importing `drizzle-orm`, `(db as Drizzle.DB).insert(r)` was a medium `db.write` on `db as Drizzle.DB.insert`, where `db.insert(r)` is a high one. A type that spelled a spread or spanned lines (`(x as [...T]).map(g)`) collapsed the receiver to `<computed>`. Each now reads as the receiver without its type, `emitter.update`, `db.insert`, `x.map`, and `this.repo.save` for `(this.repo as Repo).save()`, with no `dynamicReceiver`, so it resolves and classifies as the plain spelling does. A callee behind an assertion reads the same way: `(f as Fn)()` is `f` and `new (X as any)()` is `X`. A receiver that is not a name stays dynamic (`([...a] as T).m()` is `<computed>.m`).

A non-null assertion now builds its target from the target of what it wraps, not from its source text. Around a type assertion it answered what the assertion did, so `(x as Foo)!.save()` was the dynamic `x as Foo.save` and `(x as Foo).m!()` the dynamic `x as Foo.m`; they are now `x!.save` and `x.m!`, not dynamic. Its text also carried whatever sat inside it: `(x)!.save()` was `(x)!.save`, `x /* c */!.m()` was `x /* c */!.m`, `prisma["user"]!.create({})` was `prisma["user"]!.create`, and a chain written over lines (`this.repo` then `.items!.save()`) was `<computed>.save`. They are now `x!.save`, `x!.m`, `prisma.user!.create` and `this.repo.items!.save`. Parentheses around one still make the receiver dynamic: `(x! as Foo).m()` is the dynamic `x!.m`, as `(x!).m()` is.

`calls[].target` changes for every such call, and a call that was dynamic leaves `stats.callResolution`'s `dynamic` bucket. Some consequences need no effect plugin. A call that now resolves (`(helper as Fn)()` calling a local `helper`) adds a `via: "call"` dependency and carries the callee's effects up the chain. `if (x) (process as NodeJS.Process).exit(1)` is now a guard, as `if (x) process.exit(1)` is, and adds a rule. The drop list, a plugin's `dropCallees` and the `suppress` and `keep` prefixes now meet such a call by its plain spelling, so `(console as Console).log(x)` is the dropped `console.log` where it was kept as `console as Console.log`. Where an effect plugin classifies a call, `effects[].target` and `confidence` change, and the asserted-receiver calls `effects-prisma` classified by their segment count stop being effects. Rules, dependencies and effects are `logic` inputs, so an IR scanned before this release, compared with one scanned after, reports those Symbols as logic changes. On this repository, scanning one tree with both versions changes the target of 21 calls (`(input as LocationLink[]).map` is now `input.map`), moves 20 of them from `dynamic` to `no-match` and one to `local-scope`, and moves no fingerprint: its `aburi.json` loads no effect plugin, none of the 21 resolves, and none is `process.exit` or a dropped callee. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
