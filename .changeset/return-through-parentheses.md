A block `return` now reads its value through the parentheses around it, as a concise arrow body does, and both now take off every pair, where the concise body took one. `return (g())` used to get a `return` rule with `expr: (g())`, where `return g()` and `() => (g())` are call-only; `return (a > b ? a : b)` gave `expr: (a > b ? a : b)` where the concise spelling gave `a > b ? a : b`; and the `return (` a formatter writes around multi-line JSX put the parentheses into `expr` (`( <div className="a">{label}</div> )`). So a formatter adding or removing a pair, or a function rewritten from `() => (x ? a : b)` to `{ return (x ? a : b) }`, moved the `logic` fingerprint with no change in behaviour. Now the pair is not part of the determination or of `expr` in either spelling, a comment inside it is skipped (`return (/* c */ x)` is trivial, as `return (x)` is), and such an edit is a syntax-only change.

A comment written straight after `return` is skipped too. It used to be read as the value, so `return /* c */ g()` got a `return` rule with an empty `expr` and lost the call `g`, with any effect on it, and `return /* keep */ { a: 1 }` got the same empty `expr`, so an edit to the object moved nothing. Now the first is call-only and records `g`, and the second gives `expr: { a: 1 }`.

What moves when an IR scanned before this release is compared with one scanned after: the `logic` fingerprint of every Symbol whose block `return` value is parenthesized and is not trivial (a call or anything with a rule), of every concise arrow whose body is such a value in two or more pairs, and of every Symbol with a comment straight after a `return`. A pair holding a comment in front of a trivial value inside a larger expression is read through as well, so `return -(/* c */ x)`, `return (/* c */ x).y` and `() => !(/* c */ x)` lose the rule they had. These are reported as logic changes and trip `--fail-on changed` or `logic-changed`. A Symbol whose only rule was such a return or body, whose value is a call, and that has no effect loses the rule, so its `logic` names nothing and, moved or renamed, it is paired by name, as a body that only calls something is. On this repository, scanning one tree with both versions moves the `logic` fingerprint of 33 Symbols, every one a multi-line `return (` that Biome writes, and changes nothing but their `rules[].expr`. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
