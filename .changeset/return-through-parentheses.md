A block `return` now reads its value through the parentheses around it, as a concise arrow body does, and both take off every pair rather than one. `return (g())` used to get a `return` rule with `expr: (g())`, where `return g()` and `() => (g())` are call-only; `return (a > b ? a : b)` gave `expr: (a > b ? a : b)` where the concise spelling gave `a > b ? a : b`; and the `return (` a formatter writes around multi-line JSX put the parentheses and the line breaks into `expr`. So a formatter adding or removing a pair, or a function rewritten from `() => (x ? a : b)` to `{ return (x ? a : b) }`, moved the `logic` fingerprint with no change in behaviour. Now the pair is not part of the determination or of `expr` in either spelling, a comment inside it is skipped (`return (/* c */ x)` is trivial, as `return (x)` is), and such an edit is a syntax-only change. A comment written straight after `return`, outside any parentheses, is still read as the value.

This moves the `logic` fingerprint of every Symbol whose block `return` value is parenthesized, and of every concise arrow whose body is in two or more pairs, so an IR scanned before this release, compared with one scanned after, reports those Symbols as logic changes and trips `--fail-on changed` or `logic-changed`. A Symbol whose only rule was such a return and whose value is a call loses the rule, so it starts pairing by name and signature rather than by its `logic` fingerprint. On this repository, scanning one tree with both versions moves the `logic` fingerprint of 33 Symbols, every one a multi-line `return (` that Biome writes, and changes nothing but their `rules[].expr`. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
