The names a module exports a declaration under are an input of its `api` fingerprint. They were recorded in `derivedBy` and read by no fingerprint, so `const handler = NextAuth(options)` with `export { handler as GET }` becoming `export { handler as GET, handler as DELETE }`, a clause renaming its export (`export { connect as open }` → `export { connect as start }`) or `export default function Page` becoming `export function Page` moved nothing, and `aburi diff` reported no change: a new `DELETE` endpoint got past a CI gate unreported. The `api` input now holds each name `derivedBy` exports the Symbol under (`export-keyword` its own name, `export-default` the name `default`, `export-clause:<name>` that name), once each and sorted, so each of those edits is an API change. The input is left out when the names are the Symbol's own name alone or none, so the keyword and a clause exporting a declaration under its own name (`export function f` and `function f` with `export { f }`) agree, and so does the order a module writes its clauses in. `exportNames`, the reader both the fingerprint and the diff use, is exported.

This moves the `api` fingerprint of every Symbol exported under a name besides its own: a declaration exported through a renaming clause, or one with a name that is the module's default export (`export default function Page`, `export default Page`). An anonymous default export keeps its fingerprint. An IR scanned before this release, compared with one scanned after, reports those Symbols as API changes and trips `--fail-on api-changed`. On this repository, scanning one tree with both versions moves the `api` fingerprint of one of its 3872 Symbols, a script's `export default function vendorGrammars`, and on NestJS's of none. Rescan the base rather than comparing against a stored IR: `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
