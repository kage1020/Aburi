`aburi diff` kept only the last `--fail-on`, so `--fail-on changed --fail-on removed` gated on `removed` alone and exited 0 over a changed Symbol, without the gate line on stderr. Each occurrence now adds its clauses after the earlier ones', exactly as the comma form does: that run exits 3 with `--fail-on changed tripped (observed: 1 changed)`, as `--fail-on changed,removed` does. Each occurrence is read as a value of its own, so `--fail-on bogus --fail-on changed`, which used to gate on `changed` alone, exits 2 with `--fail-on value "bogus" is invalid: unknown token "bogus"`. `runDiff` takes a list of `--fail-on` values as well as one, and refuses an empty list as it refuses an empty value, with the same `FailOnParseError` before anything is written.

Every other option that takes a value kept its last one too and dropped the earlier ones without a word: `--config`, `--output-dir`, `--format`, `--max-bytes`, `--base`, `--head`, `--ir` and the `--output` of `init` and `explain`. A second occurrence now exits 2 before anything is read or written, naming the option and both values: `--config is given more than once ("a.json", then "b.json"): pass one`. That holds when the second value is one the option refuses on its own, too: `--format json --format bogus` names the repeat, where it used to report only that `bogus` is invalid. `--ignore` still adds up, and a flag, which takes no value, or either half of a `--x` / `--no-x` pair, can still be repeated, the last one written applying. A CI script that repeats `--fail-on` now gates on every clause it names, and can turn red on a change the last clause alone let through; one that repeats any other option that takes a value exits 2 until it passes it once.

An option that takes a path now exits 2 on an empty value, before anything is read or written: `error: option '--config <path>' argument '' is invalid. a path must not be empty`. `--config ""` used to fall back to `ABURI_CONFIG` or a discovered `aburi.json`, `--output-dir ""` wrote into the working directory, where `aburi diff` first removed any `diff.json`, `diff.md` and `diff.full.md` it found, and `aburi diff main..HEAD --head ""` ran as if `--head` were absent. `init --output ""`, `explain --ir ""`, `explain --output ""` and `diff --base ""` exited 2 already, with a message about a directory or a missing input instead. A script that builds a path option from a variable that can be empty exits 2 until it leaves the option out in that case.

Only argument handling changes. Nothing a scan or a diff writes is different, so an IR scanned before this release, compared with one scanned after, shows no change the release caused.
