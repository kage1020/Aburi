LSP enrichment now hovers the call's own method for a `this.<method>` / `super.<method>` call. It searched the line for `this.save` as a bare substring, so an occurrence that was not the call drew the hover: `this.saveAll(); return this.save()` resolved `this.save` to the `save` of whichever class declares `saveAll`, `this.handlers.forEach(() => this.handle())` reached the `handle` of whichever class declares `handlers` instead of the override, and `mythis.foo(); this.foo()` linked `this.foo` to an unrelated class, all at `high` confidence, and the caller's `signature.inferredThrows` took that member's `@throws`. The search now matches whole tokens by the full identifier rules (`this.保存する(); this.保存()`), passes over a property of something else (`ctx.this.save()`), and skips strings and comments on the line, while a call inside a template literal's `${…}` is still found. An optional call, `this?.save()`, was never found and now is. Where a prose apostrophe hides the call from that reading, as in JSX text (`<p>Don't {this.title()}</p>`), the call is found when it is the line's only occurrence; with two (`<p>Don't {this.save()} {this.save()}</p>`) neither is hovered any more.

Calls change only where the search used to land off the call — either on the wrong member, or inside a string or comment where the hover answered nothing — and on the two shapes just named. With an effect plugin loaded, a caller whose call now resolves differently, or at all, inherits different effects, which moves its `logic` fingerprint, so an IR scanned before this release, compared with one scanned after, reports it as changed. Without `lsp.enabled` or without an effect plugin, no fingerprint moves. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides and is unaffected.
