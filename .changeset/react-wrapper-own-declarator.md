A `const` is now a `framework:react:context`, `framework:react:forward-ref` or `framework:react:memo` only when its own initializer is the `createContext(...)`, `forwardRef(...)` or `memo(...)` call. A `const` Symbol's node is its whole declaration statement, and the first call anywhere in it decided the role whichever name was asked about: in `export const ThemeContext = createContext("light"), DEFAULT_THEME = "light"` both names were contexts, in `export const A = memo(X), B = forwardRef(Y)` `B` was a memo, and in `export const theme = getTheme(), Ctx = createContext(null)` `Ctx` had no role. A const that only contained a wrapper call took its role too: a route table (`[{ path: "/", element: memo(Page) }]`), a handler map (`{ save: () => forwardRef(…) }`), `new Holder(memo(Row))`, `flag ? memo(A) : B`, and a name destructured from one (`const { displayName } = memo(Row)`). The initializer is read through `as`, `satisfies`, `!` and parentheses, as `@aburi/lang-typescript` reads it, so `memo(Row) as typeof Row` is still a memo, and its outermost call names the role, so `memo(forwardRef(…))` is still a memo and `withTheme(memo(Row))` is none. `extractWrapperCall` now takes the Symbol's name as a second argument.

The `api` fingerprint reads `extKind`, so it moves for every const this reclassifies: a name declared beside a wrapper, or holding one inside its initializer, loses the role; a wrapper declared after a name initialised by another call gains its own; and a wrapper declared after one of another kind changes role. An IR scanned before this release, compared with one scanned after, reports those Symbols as api changes, and the Markdown projection's Boundary effect surface, which lists Symbols by a `framework:` extKind, gains or loses those of them that have effects. A wrapper declared after one of the same kind keeps its kind; at most its `derivedBy` changes (`React.memo` for `memo`), which no fingerprint reads. A const that its statement declares alone, initialised by the wrapper call itself, is read as before. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
