A default export written as a call handed a function, which `@aburi/lang-typescript` now gives a `<default>` `const` Symbol, can take a framework role. `@aburi/framework-next` gives an App Router file's role (`page`, `layout`, `template`, `loading`, `error`, `not-found`) to a default-exported `const` that carries `call-argument-function`, so `export default withAuth(function Page() { … })` and `const Page = withAuth(() => { … }); export default Page` are pages; a `const` default export whose call is handed no function is still not one. `@aburi/framework-react` reads `export default memo(function Row() { … })` as a `framework:react:memo`, and `forwardRef(…)` as a `framework:react:forward-ref`, as it reads the same call bound to a `const`. It reads the call through `@aburi/core`'s `declaratorValue`, which now returns a default export statement's value, read through `unwrapValue`, when asked for the name `<default>`, and `null` for any other name. `@aburi/types` exports the token as `CALL_ARGUMENT_FUNCTION_DERIVED_BY`; nothing a scan writes changes.

The `api` fingerprint reads `extKind`, so it moves once for a `const` App Router component bound apart from its default export. One with no role takes `framework:next:<role>`. One that `@aburi/framework-react` classified moves too when `@aburi/framework-next` is listed before it in `frameworks`, since the first framework that answers classifies the Symbol: `const Page = memo(function Page() { … }); export default Page` in `app/**/page.tsx` goes from `framework:react:memo` to `framework:next:page`. Listed the other way round, it stays a memo. An IR scanned before this release, compared with one scanned after, reports those Symbols as api changes, and the Markdown projection's Boundary effect surface, which lists Symbols by a `framework:` extKind, gains or loses those of them that have effects. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
