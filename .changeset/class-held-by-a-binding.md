A class expression a binding holds is now read as the class it declares. `export const Registry = class { … }` was a `const` with no body, so the class's methods had no Symbol and its methods, field initialisers and static blocks were walked on no Symbol, which left their calls and effects out of the IR. It is now `kind: "class"`, named by the binding, with its members as `class Registry { … }` gives them (`Registry.reset`, `Registry::make`) and `derivedBy` carrying `variable-assigned-class`. A namespace written beside it merges as it does into a declared class, its exports on the static side (`Registry::O`). It is read through parentheses, `as`, `satisfies` and `!`, and with `let` and `var`. `const Registry = class Inner { … }` is named `Registry`, since `Inner` is in scope only inside the class body. A class the binding does not hold directly, handed to a call (`const A = mixin(class { … })`), in a conditional or under `new`, stays in a `const` and is walked by no Symbol.

Being a class, it takes a class's drop hints: a class of fields alone is now dropped as a `pure DTO`, and one of `static readonly` literals as `pure constants`, where the `const` was kept. Its field initialisers and static blocks are walked on it, but a class of fields alone is still a `pure DTO`, so `seed = compute()` in one is dropped with its calls, as it is in a declared class of fields.

An IR scanned before this release, compared with one scanned after, reports each such binding as changed, its `api` and `syntax` fingerprints moved (`kind` is an `api` input), and its methods as added, tripping `--fail-on changed`, `api-changed`, `syntax-changed` or `added`; a binding whose class is now a `pure DTO` or `pure constants` is reported as `dropped-toggled` to dropped instead, tripping `--fail-on dropped-toggled` or `dropped-toggled:to-dropped`. Calls into the class now resolve to its members (`Registry.make()` to `Registry::make`), so their callers' `calls[].resolved` and `dependencies[]` change and, with an effect plugin, they inherit the members' effects and their `logic` moves, tripping `--fail-on logic-changed`; a caller's `new Point()` no longer resolves to a class now dropped. Rescan the base rather than comparing against a stored IR; `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
