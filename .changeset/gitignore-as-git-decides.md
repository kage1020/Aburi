---
"@aburi/core": minor
---

`.gitignore` is now matched by Aburi's own port of git's matcher rather than the `ignore` package, so discovery keeps and drops the files git does, apart from the differences that stay by design: matching is case-sensitive whatever `core.ignoreCase` says, a tracked file that matches a rule is still left out, `.git/info/exclude` and `core.excludesFile` are not read, and a rule over 4,096 bytes or a `.gitignore` of 100 MiB or more ends the scan with the file named.

A deeper `.gitignore` that re-includes a directory (`!ourlib/` under a root `third_party/*`) now brings its files back; they used to be missing from the IR, `stats.totalFiles` and `stats.skippedFiles` alike. `src/**/` matches directories only, a lone `!` no longer undoes the rules before it, and POSIX classes, `\?` and a leading `]` in a bracket now match. Some files move the other way: a trailing tab or no-break space is now part of the rule, so `dist<TAB>` no longer leaves out `dist/`; `?` takes one byte, so `?.ts` no longer matches `é.ts`; a reversed range such as `[z-a]` now matches its first end; and a rule is cut at a NUL byte, so `foo<NUL>bar` now leaves out `foo`. Rule length is measured in bytes, and a rule git can never match, such as one with an unterminated bracket, now matches nothing instead of failing the scan. A rule built of many `*`, such as `*a*a*a*a*a*a*a*a*a*a*b`, no longer takes seconds for each file it is asked about.

Where a `.gitignore` now decides a file differently, an IR scanned before this release, compared with one scanned after, reports the Symbols of each such file as added or removed, once; Symbols in unchanged files that call into them can report changed fingerprints, because the effects that propagate to them changed; and a component's `languages` is counted over the new set of files. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with this release and is unaffected.
