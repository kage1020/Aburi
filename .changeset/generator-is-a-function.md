A generator function is now read as a function wherever the plugin asks whether a value is one: a binding (`export const pages = function* () { yield fetchPage() }`, `async function*` included), a class field, an object entry, a function a `const` hands to a call, and a registration's handler (Koa's `app.use(function* (ctx, next) { … })`). Before, `generator_function` was outside the set, so the binding was a `const` with no body and `fetchPage` and its effects were on no Symbol; a class field holding a generator stayed on the class, so constructing the class reported what iterating the generator does, and a class of nothing but generator fields was dropped as a `pure DTO` with the calls it carried; and an object entry, a call argument or a registration handler written as a generator was not walked as a body. Each now gets what an arrow in the same place gets: the binding is `kind: "function"` with `signature.generator: true`, the field and the entry are `kind: "method"` Symbols of their own, and the call's const and the registration take the generator as a body.

Symbols bound to a generator change `kind` and gain a `signature`, calls and effects, so an IR scanned before this release, compared with one scanned after, reports them as changed on every axis; a generator field becomes a new `method` Symbol and leaves its class's calls and effects, and a class of only generator fields stops being dropped (`dropped-toggled` to kept). On this repository, scanning one tree with both versions gives the same Symbols and fingerprints, since its generators are all declarations. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
