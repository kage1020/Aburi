A function's parameter list now reaches its `syntax` fingerprint, for a function, a method, a constructor, an accessor and a field or an object entry that holds a function. Only the body was serialized, and the `api` axis reads a parameter's type and form but not its name, its destructuring pattern or its default's value, so changing the key a destructured parameter reads (`{ a: b }` → `{ c: b }`), the hole an array parameter skips, a default's value (`limit = 20` → `limit = 10`) or the name of a parameter the body does not use moved no fingerprint and `aburi diff` reported no change. Each is now a syntax-only change. A parameter's decorator (`@Inject(X)` → `@Inject(Y)`) and a parameter property's modifier (`private s` → `public s`) are in the list too, so an edit to either now moves the method or constructor as a syntax-only change, where only its class moved before. The list goes in whole, so a parameter's type, `?` or `...`, already an `api` change, now moves `syntax` too, and `--fail-on syntax-changed` counts it; a return type or a type parameter, outside the list, still moves `api` alone.

A trailing comma after the last parameter changes nothing, and neither do the parentheses a formatter puts around an arrow function's lone parameter (`x => …` → `(x) => …`), wherever the arrow is written: in a body (`items.map(x => x.id)`), as a class field or an object entry, or handed to a call. Those parentheses moved the `syntax` fingerprint of whatever held such an arrow before. A function with no parameters keeps its fingerprint, and so does a declaration already described whole, for its own list: an overload signature, an abstract member, a `declare` function, a const whose function is handed to a call, a class field holding one, a route registration.

This moves the `syntax` fingerprint of every function, method or constructor that has a parameter and a body, and of every Symbol whose normalized string holds an arrow with a parenthesis-free parameter, so an IR scanned before this release, compared with one scanned after, reports those Symbols as syntax-only changes, with `api` and `logic` unchanged, and trips `--fail-on changed` or `syntax-changed`. On this repository, scanning one tree with both versions moves the `syntax` fingerprint of 2119 of its 3894 Symbols and no `api` or `logic` fingerprint. Its formatter puts every arrow parameter in parentheses, so none of those moves for an arrow; on the `nest` repository, written without them, reading an arrow's lone parameter as the parenthesised spelling moves 454 of 5404 Symbols on its own. Rescan the base rather than comparing against a stored IR: `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
