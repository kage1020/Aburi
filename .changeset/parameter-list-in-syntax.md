A function's parameter list now reaches its `syntax` fingerprint, for a function, a method, a constructor, an accessor and a field or an object entry that holds a function. Only the body was serialized, and the `api` axis records a parameter's type and form but not its name, its destructuring pattern or its default's value, so changing the key a destructured parameter reads (`{ a: b }` → `{ c: b }`), the hole an array parameter skips, a default's value (`limit = 20` → `limit = 10`) or the name of a parameter the body does not use moved no fingerprint and `aburi diff` reported no change. Each is now a syntax-only change. A trailing comma after the last parameter, and the parentheses a formatter puts around a lone arrow parameter (`x => …` → `(x) => …`), still change nothing. A function with no parameters keeps its fingerprint, and so does a declaration already described whole: an overload signature, a const whose function is handed to a call, a route registration.

This moves the `syntax` fingerprint of every function, method or constructor that has a parameter, so an IR scanned before this release, compared with one scanned after, reports those Symbols as syntax-only changes, with `api` and `logic` unchanged, and trips `--fail-on changed` or `syntax-changed`. On this repository, scanning one tree with both versions moves the `syntax` fingerprint of 2107 of its 3872 Symbols and no `api` or `logic` fingerprint. Rescan the base rather than comparing against a stored IR: `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
