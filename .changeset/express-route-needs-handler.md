---
"@aburi/framework-express": minor
---

A module-level call is now a `framework:express:route` only when it is handed a handler after its path, not whenever its method is `get`, `post`, `put`, `patch`, `delete` or `all`. `cache.delete("key")`, `settings.get("port")`, `url.searchParams.delete("x")`, `axios.post(url, { id })` and Express's own settings getter `app.get("env")` were classified as routes, at `medium` confidence in a file without an Express import, and adding an unrelated `import express` to such a file was reported as a confidence change. The first argument is taken as the path, and its shape is not checked, so `cache.put(key, value)` is still a route. At least one argument after it must be handler-shaped: an inline function, an identifier, a member path (`users.list`, `handlers["list"]`), a call (`asyncHandler(listUsers)`, `passport.authenticate("google", { scope })`), a choice between handlers (`isProd ? cached : live`, `custom || defaultHandler`, `options.handler ?? fallback`), or an array or spread of handlers. A chain that has called `.route(path)` with a literal path beginning with `/`, on any receiver, has written the path already, so `app.route("/users").get(listUsers)` needs the handler alone, and so does a call whose first argument is a spread (`app.get(...routeArgs)`). Arguments and the receiver chain are read through `as`, `satisfies`, `!` and parentheses, as `@aburi/lang-typescript` reads them to name the registration, and that now holds for `.use(...)` too: `app.use(logger as RequestHandler)` is middleware and `app.use("/api", apiRouter as Router)` a mount, as their bare spellings are. `hasRouteArguments` is exported.

The `api` fingerprint reads `extKind`, so it moves for every call this classifies differently. Most of the calls that lose `framework:express:route` were never routes, but these registrations lose it too and are no longer classified at all: a route whose only handler is awaited (`app.get("/x", await makeHandler())`), constructed (`app.get("/x", new AsyncHandler(listUsers))`) or written behind an old-style assertion (`app.get("/x", <RequestHandler>listUsers)`); a route registered on a name an `app.route(path)` call was bound to (`const r = app.route("/users")`, then `r.get(listUsers)`), which is shaped like `cache.get(key)` and which the plugin, reading one statement at a time, cannot tell apart from it; and an `app.route(...)` chain whose path is not a literal beginning with `/` (`app.route(USERS_PATH).get(listUsers)`). A `.use(...)` call whose argument is wrapped gains its kind. An IR scanned before this release, compared with one scanned after, reports those Symbols as api changes, and the Markdown projection's Boundary effect surface, which lists Symbols by a `framework:` extKind, gains or loses those of them that have effects. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
