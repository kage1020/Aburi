A class with a `static { … }` block is no longer dropped as a `pure DTO`. A static block runs when the class is defined and its calls are walked on the class, but the drop hint counted only methods and function-valued fields as behaviour. So `export class Registry { static items: string[] = []; static { prisma.user.deleteMany() } }` was dropped, with all-zero fingerprints and empty `calls` and `effects`, while the same class without `items` was kept with the `db.write`. Adding the field was reported only as a `to-dropped` entry under Dropped changes, and the block's effect left the report. The class is now kept either way, and adding the field is a syntax-only change. An index signature and a comment still leave a class of fields a `pure DTO`. A comment no longer turns a class of `static readonly` literals into a `pure DTO` instead of `pure constants`; both are dropped with the same fingerprints, so only `dropReason` changes. A field's initializer is still not read as behaviour: a class of fields one of which holds a call (`seed = makeSeed()`, `static rows = db.load()`) is still a `pure DTO`, and those calls are dropped with it.

Every class of fields and a static block with no method is now kept, so an IR scanned before this release, compared with one scanned after, reports it as `dropped-toggled` to kept, with fingerprints, calls and effects it did not have, and `dependencies[]` gains the block's resolved calls. A Symbol whose call resolves to such a class (`new Registry()`) inherits the block's effects as propagated ones and moves `logic`, which trips `--fail-on logic-changed` or `changed`. On this repository, which has no such class, scanning one tree with both versions gives a byte-identical IR. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
