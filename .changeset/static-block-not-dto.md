A class with a `static { … }` block is no longer dropped as a `pure DTO`. A static block runs when the class is defined and its calls are walked on the class, but the drop hint counted only methods and function-valued fields as behaviour. So `export class Registry { static items: string[] = []; static { prisma.user.deleteMany() } }` was dropped, with all-zero fingerprints and empty `calls` and `effects`, while the same class without `items` was kept with the `db.write`. Adding the field was reported only as a `to-dropped` entry under Dropped changes, and the block's effect left the report. The class is now kept either way, and adding the field is a syntax-only change. An index signature and a comment still leave a class of fields a `pure DTO`. A comment among a class's `static readonly` literals no longer makes it a `pure DTO` rather than `pure constants`; both drop it with all-zero fingerprints, so only `dropReason` changes and `aburi diff` reports nothing. A field's initializer is still not read as behaviour: a class of fields one of which holds a call (`seed = makeSeed()`, `static rows = db.load()`) is still a `pure DTO`, and those calls are dropped with it.

Every class of fields and a static block with no method is now kept, so an IR scanned before this release, compared with one scanned after, reports it as `dropped-toggled` to kept, with fingerprints, calls and effects it did not have; that trips `--fail-on dropped-toggled` and `dropped-toggled:to-kept`. The block's resolved calls join `dependencies[]`, and so do the calls that reach the class: a dropped Symbol is no call target, so a caller's `new Registry()` did not resolve to it and now does, in `calls[].resolved` and `dependencies[]`, with or without an effect plugin. Where an effect plugin classifies the block's calls, that caller also inherits their effects as propagated ones, and unless it already carried the same effect, its `logic` moves, which trips `--fail-on logic-changed` or `changed`. On this repository, which has no such class, scanning one tree with both versions gives a byte-identical IR. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugin and is unaffected.
