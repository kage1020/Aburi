# Notes on the 2026-10-01 run

Read alongside [`2026-10-01.md`](./2026-10-01.md), which holds the tables, and
[`2026-10-01.json`](./2026-10-01.json), which holds every sample. The previous run
is [`2026-09-01`](./2026-09-01-notes.md); every `head` and `base` pin is the same in
both, so the counters compare directly.

Environment: 4 vCPU AMD EPYC 7763, 16 GiB RAM, Linux, **Node v24.21.0**, `aburi`
0.4.0 built from `3b917f21` by the `Benchmark` workflow. Last month was a Xeon @
2.10 GHz on Node 22. Both the runner and Node changed, so this run splits the way
the README asks: counters carry across runners, cost does not.

## Which commits the two runs measured

This run measured `3b917f21`; the workflow says so in the pull request, though not
yet in the results file. The 2026-09-01 run was built "from the working tree", and
the file does not say which tree. Rebuilding candidates and scanning the same pins
settles it: **`e257d20`** (#242) reproduces every 09-01 counter exactly on
`express`, `nest`, `trpc` and `shadcn-ui`, and `1127938`, the commit that landed
the 09-01 results, does not — #246 merged between the run and the commit that
recorded it. Every attribution below is measured against `e257d20`.

## Counters: what the other moves are

Each of these was traced by scanning the pinned tree with builds on either side of
the change and diffing the IR Symbol by Symbol.

**`shadcn-ui` kept 10,098 → 10,090 is eight phantom Symbols gone, not a loss.** No
Symbol was added and eight were removed, all `const`, all from two of the #250 files:

| File | Symbols that disappeared |
|---|---|
| `packages/shadcn/src/commands/eject.test.ts` | `actual`, `mock`, `formatMonorepoMessage`, `getMonorepoTargets`, `isMonorepoRoot` |
| `packages/shadcn/src/commands/preset.test.ts` | `actual`, `mock`, `existsSync` |

Each file opens with `vi.mock(…, async (importOriginal) => { const actual = await
importOriginal<typeof import("…")>(); return { ...actual, existsSync: vi.fn() } })`.
While the grammar refused the `import(...)` type argument, error recovery surfaced
the factory's local `actual` and the returned object's keys as top-level `const`
Symbols, every one of them sharing the `vi.mock` call's line range. Once #250 let
the file parse, they went. The other 10,668 Symbols are identical by file, name,
kind and drop state. This corrects the 09-01 note that recovery on these files lost
no data: it also invented some.

**`express` calls 240 → 412 (+72%) is #246.** `2dfb45d` ("Walk the function a
wrapper or a registration argument was hiding") landed the evening after the 09-01
run; `e257d20` gives 240 and `1127938` gives 412, and nothing in between touches
extraction (#254 is lockfile-only, #253 is the harness). `app.get("/", function
() { … })` is how Express is written, and those callbacks' calls are now counted.
The growth is almost all `noMatch` (+149) and `dynamic` (+9), with resolved +14, so
**resolved % falling 12.1% → 10.4% is the denominator growing**, not resolution
getting worse. Read it that way next month too.

**`nest` symbols 5,284 → 5,397 (+113) is #272**, "Extract the declarations that
are written without a body": `9e32538` gives 5,284 and `7f9ed89` gives 5,397, with
kept and dropped matching this run exactly on both sides. Every one is an addition
and none is a removal:

- 58 abstract methods (`AbstractHttpAdapter`, `FileValidator`, …), dropped as
  `empty body`;
- 22 `declare class` error types in `external/kafka.interface.ts`, kept, each with
  its constructor (22);
- the `declare namespace fastifyMiddie` block in `fastify-middie.ts` (5 types,
  2 interfaces, 1 const), `type QoS` in `mqtt-options.interface.ts`, and two
  `declare const module` in the HMR samples.

**`nest` resolved 192 → 212 is #324**: a call written `ClassName.m()` now resolves
to the static member. All 20 new edges are one, mostly
`RouteConflictDetector.*` and `RouteSpecificitySorter.*` calling their own private
statics. 2.0% → 2.2% is still the lowest resolution rate in the sweep, and the
reason in the 09-01 notes (constructor-injected receivers) has not changed.

**`trpc` kept 1,525 → 1,524 is #272 too, and is the one move here worth a second
look.** `packages/server/src/observable/operators.test.ts` declares
`declare interface CustomEventEmitter<T> { … }` and then `class
CustomEventEmitter<T> implements CustomEventEmitter<T> {}`. Before #272 the
`declare` wrapper hid the interface and the Symbol was the class; now both reach
the extractor, the one-Symbol-per-entity fold (#230) merges them, and the kind it keeps is
`interface`, which is dropped as a data model. The class is what `new
CustomEventEmitter()` constructs, so the merge should probably keep `class`. It is
one Symbol in a test file, but the same fold applies to any class merged with an
ambient interface.

Smaller: `cal-com` is the one repo where resolution itself improved — `noMatch` −68
against resolved +87.

## Cost: not attributable from this run

- **Scan wall −19% to +2%**, and `init` −16% to −25% on every repo. Consistent with
  the CPU generation; not evidence of anything in the code.
- **Scan peak RSS rose on all nine, +13% to +67%** (`zod` +67%, `nest` +64%,
  `hono` +34%, `trpc` +33%). Diff RSS rose +14% to +72%, `shadcn-ui`'s −18% the only
  fall. Node 22 → 24 changed V8's default heap sizing, and that is fully confounded
  with the code here. Only an A/B of two commits on one runner and one Node version
  separates them.
- **Against the SLA**: performance.md §2 allows 2 GiB. The high-water mark is
  `cal-com`'s diff at 965 MiB, up from 658 MiB (+47%), and the repo holding the mark
  changed (`shadcn-ui`'s diff fell 822 → 674 MiB). Still under half the budget, but
  "up everywhere" and "+47% at the maximum" are the pair to watch next month.
- **`zustand`'s diff/scan ratio went 1.66× → 3.68×.** The other eight sit at
  2.05–2.38× (1.66–2.23× last month). Its scan got *faster*, so the CPU does not
  explain it, but `aburi diff` includes a `git worktree add`, and on 49 files that
  fixed disk cost dominates, and the disk changed with the runner. Carry the ratio
  forward rather than the seconds.

## Determinism holds

`✓` on all nine. `summariseScans` compares all three hashes, so the tick is sound,
but only `hashes[0]` is persisted, so it cannot be re-derived from the file alone.

## Caveats

- One machine, one run per repo. The runner and Node both changed since 09-01.
- The attributions above come from single scans of one repo at each of two builds
  (`e257d20`, `1127938`, `9e32538`, `7f9ed89`, `3b917f21`), run on a separate
  machine on Node 22; only counters were compared across them, never cost.
- The results file does not record the Aburi commit it measured, which is why the
  first section had to be reconstructed.
